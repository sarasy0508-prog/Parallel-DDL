# Parallel-DDL — 产品需求文档(PRD)

> 版本:v0.1 草案
> 更新:2026-05-20
> 状态:首轮评审已完成,部分细节待后续敲定(详见第 7 节)

## 1. 产品概述

### 1.1 定位
个人专属的 DDL 拆解与执行工具。用户输入"任务描述 + DDL",AI 把它拆成可立即执行的小步骤;配合"早 / 中 / 晚"的日历安排,帮用户把"压线赶 due"变成"按节奏推进"。

### 1.2 目标用户
**单人使用**,主要面向学生群体:
- 本科生、硕士生、博士生
- 典型 DDL 场景:个人作业、小组作业、小测、期中考试、期末考试、论文、实验报告

### 1.3 部署形态
- 现阶段:**PC 浏览器**
- 后续规划:可能升级为桌面应用(Electron / Tauri 等待选)

### 1.4 个人衡量目标
不追求商业指标,以下作为自我衡量标准(可由作者继续调整):
- 不再出现 last-minute 才动手的 DDL,尽量提前 1–2 天完成
- AI 拆解出的步骤可以直接执行,不需要再手工二次拆解
- 每天至少打开一次,确认当天的早 / 中 / 晚安排

## 2. 核心交互模式:项目看板(Kanban)

### 2.1 展现
- 每个任务作为一个独立卡片,横向排列
- 卡片内垂直列出该任务的所有步骤(Checklist)

### 2.2 排序
- 默认:按**创建时间**排列
- 用户可拖拽卡片改变顺序(用户拖拽后的顺序应被持久化)

### 2.3 不做的事
- 不做过滤 / 搜索功能(伪需求,任务量级不大)
- 不做提醒 / 通知(邮件、浏览器推送均不做)

### 2.4 任务状态机
共 5 个状态:**草稿 / 进行中 / 已完成 / 已逾期 / 已归档**

| 状态 | 进入条件 | 视觉表现 |
| --- | --- | --- |
| 草稿 | 用户刚输入但还没确认拆解 | 普通卡片(浅色) |
| 进行中 | 已确认拆解,有未完成步骤 | 普通卡片 |
| 已完成 | 所有步骤都被勾选 | 卡片显示"归档"按钮,由用户手动决定是否归档(**不自动归档**) |
| 已逾期 | DDL < 当前时间 且 状态非"已完成" | 卡片整体变红 + 标题前加警示 emoji,**不自动归档** |
| 已归档 | 用户在"已完成"状态下手动点击归档 | 从主看板隐藏(可在归档区查看) |

### 2.5 任务级操作
- **创建**:输入任务描述 + DDL + 选择单步时长(5/10/25/45min) → 触发 AI 拆解
- **编辑**:卡片标题、DDL 可后续编辑
- **删除**:点击删除即生效,**不需确认弹窗,不可撤销**
- **归档 / 取消归档**:在"已完成"状态下手动触发

### 2.6 步骤级操作
- **勾选 / 取消勾选**:在看板上直接点击 checkbox
- **编辑文字**:点击步骤文字进入编辑
- **添加步骤**:卡片底部"+ 添加步骤"按钮
- **删除步骤**:每个步骤右侧删除图标
- **拖拽重排**:步骤可在卡片内上下拖动改顺序
- **安排到日历**:点击步骤上的"安排"按钮 → 弹出日期 + 时段选择器(详见第 4 节)

## 3. AI 拆解模块

### 3.1 模型
- **DeepSeek API**(具体型号、密钥管理后续敲定)

### 3.2 输入
- 任务描述(中文)
- DDL
- **单步时长**:用户从 `5min / 10min / 25min / 45min` 四档中选一档,AI 据此控制每步颗粒度

### 3.3 输出
- 中文步骤列表
- **步骤数量不限**,由 AI 根据任务自行决定
- 每个步骤应能在所选单步时长内完成

### 3.4 交互
- 点击"AI 拆解" → 显示 Loading 动画 → 拆解完成后步骤自动填入卡片
- 拆解结果生成后,**用户可自由编辑**(改名 / 增删 / 重排)
- **不支持二次 AI 拆解**:一旦用户编辑过,以用户的最终编辑为准,不再让 AI 覆盖

### 3.5 v0.1 范围外(明确不做)
- AI 调用失败 / 超时 / 输出格式错误的兜底重试 → 暂不考虑
- 多语言输入输出 → 仅支持中文

### 3.6 待定(转入下一轮)
- 完整的 system prompt 文本 + few-shot 示例
- 输出格式(JSON / Markdown / 纯文本)
- AI 调用是前端直连还是后端代理(密钥安全)

## 4. 日历模块

### 4.1 视图
- **月视图**:全局浏览,看到所有任务的 DDL 分布
- **日详情**:点击某天 → 三段式列表(早 / 中 / 晚),展示该日计划完成的步骤

### 4.2 时段定义
- "早 / 中 / 晚" 仅作为分类标签,**不绑定具体时间区间**
- 用户**不可自定义**时段定义

### 4.3 关联机制(看板 → 日历)
- 唯一入口:在看板的步骤上点击"安排" → 弹出日期 + 时段选择器
- 单个步骤可被排到**多个 (日期, 时段) 组合**
- 同一 (日期, 时段) 槽位可放**多个步骤,无上限**

### 4.4 明确不做
- 不能在日历槽位上**直接新增**步骤(只能从看板的步骤入口反向安排)
- 日历**只读展示**,不能在日历界面勾选完成(完成操作仅在看板)
- 步骤跨天未完成时,**不自动顺延**(由用户自行处理)
- 不做提醒 / 通知

## 5. 数据模型

### 5.1 持久化方式
- **本地 JSON 文件**,**不接入数据库**
- 单人本地版,不需要 Users 表,也不需要登录态

### 5.2 实体(字段细节后续完整 schema 设计)

#### Project(任务)
| 字段 | 说明 |
| --- | --- |
| `id` | 唯一标识 |
| `title` | 任务名 |
| `ddl` | 截止时间 |
| `created_at` | 创建时间(用于默认排序) |
| `status` | 草稿 / 进行中 / 已完成 / 已逾期 / 已归档 |
| `order` | 用户手动拖拽后的显示顺序 |
| `step_size` | 用户选择的单步时长(5/10/25/45 min) |
| `steps` | 步骤列表 |

#### Step(步骤)
| 字段 | 说明 |
| --- | --- |
| `id` | 唯一标识 |
| `project_id` | 所属任务 |
| `content` | 步骤内容(中文) |
| `done` | 是否完成 |
| `order` | 在卡片内的显示顺序 |
| `schedules` | 关联的 `(date, slot)` 列表,`slot ∈ {早, 中, 晚}` |

### 5.3 待定
- 字段类型、必填、长度上限
- JSON 文件的物理结构(单文件 / 多文件 / 索引)
- 是否需要导入 / 导出(用于备份与设备迁移)

## 6. 用户工作流

```
1. 创建任务
   用户输入【任务描述 + DDL + 单步时长】
       ↓
2. AI 拆解
   点击"AI 拆解" → Loading → 步骤列表生成,任务进入【进行中】状态
       ↓
3. 用户调整(完全控制权)
   - 改名:修改不准确的步骤
   - 增删:添加遗漏 / 删除多余
   - 拖拽:调整步骤顺序
       ↓
4. 安排执行
   - 在步骤上点"安排" → 选日期 + 早/中/晚 → 关联到日历
   - 一个步骤可关联到多个时段
       ↓
5. 执行与勾选
   - 在看板上勾选完成步骤
   - 日历同步反映安排,但日历只读
       ↓
6. 收尾
   - 全部勾完 → 状态变【已完成】 → 出现归档按钮 → 用户手动归档
   - DDL 过期未完成 → 卡片变红 + 警示 emoji,不自动归档
```

## 7. 待办与下一步(转入后续讨论)

按阻塞开发的优先级排序:

1. **AI Prompt 设计** — system prompt、few-shot、输出格式 schema
2. **技术栈选型** — 前端框架(React / Vue / Svelte / 其他)、构建工具、JSON 文件读写方案
3. **JSON 数据 schema** — 字段类型、必填、长度限制、文件结构
4. **UI 视觉与交互稿** — 看板版式、日历版式、空状态、错误 Toast 风格
5. **是否需要 JSON 导入 / 导出** — 备份与设备迁移场景
6. **AI 调用安全** — 前端直连暴露密钥 vs 后端代理
7. **个人衡量目标的具体表述** — 是否保留 / 怎么写
