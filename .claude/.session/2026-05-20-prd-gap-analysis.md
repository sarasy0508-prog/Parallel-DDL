针对学生群体(本科生、研究生、博士生),主要的ddl包括但不仅限于:,个人作业,小组作业,小测,期中考试,期末考试,论文,实验报告
- 成功指标:留存?日活?任务完成率?

- 任务整体完成(所有步骤勾完)如何呈现?自动归档还是留在看板?

# 第一轮评审完成(2026-05-20)

用户对七大缺口逐条作答,以下结果已合并进 `PRD.md` v0.1 草案。

## 已敲定决策汇总

### 产品定位
- 单用户、个人使用,无协作
- 仅 PC 浏览器(后续可能升级桌面应用)
- 目标用户:学生群体(本/硕/博)
- DDL 类型:作业、小测、期中、期末、论文、实验报告
- 衡量指标:对个人项目无意义,改为"个人目标"占位(待用户决定保留 / 删 / 改)

### 看板模块
- 默认按创建时间排,可拖拽
- 不做过滤搜索
- 状态机:草稿 / 进行中 / 已完成 / 已逾期 / 已归档
- 逾期:变红 + 警示 emoji,不自动归档
- 全部完成:用户手动决定归档(不自动)
- 删除任务:无确认、不可撤销
- 步骤可拖拽重排

### AI 模块
- 模型:DeepSeek
- 中文进、中文出
- 步骤数量不限,AI 自行决定
- **新增设计**:用户从 5/10/25/45min 四档中选单步时长,AI 据此拆解(这是 PRD 原文没有的关键输入)
- Loading 动画展示
- 失败 / 超时:暂不考虑
- 用户编辑后**禁止二次 AI 拆解**,以用户最终编辑为准

### 日历模块
- 入口:看板步骤上"安排"按钮 → 弹日期 + 时段选择器
- 一个步骤可排到多个时段
- 早 / 中 / 晚:纯标签,无时间定义,不可自定义
- 同一槽位可放多个步骤,无上限
- 日历**只读**,不能反向加步骤,不能在日历完成勾选
- 不做通知 / 提醒
- 跨天未完成不自动顺延

### 数据模型
- **不接数据库**,用本地 JSON 文件持久化
- 单人本地版,不需要 Users 表,不需要登录

## 仍待敲定(进入后续轮次)

按阻塞优先级:

1. AI Prompt 模板与输出 schema
2. 技术栈(前端框架、JSON 读写)
3. JSON 数据 schema 字段细节(类型、必填、长度)
4. UI 视觉 / 交互稿
5. 是否需要 JSON 导入导出
6. AI 调用安全(前端直连 vs 后端代理)
7. 个人衡量目标具体表述

## 待用户确认的推断

我在写 v0.1 草案时做了几处合理推断,需要用户确认:

1. **创建任务流程**:推断为"用户填任务描述 + DDL + 单步时长 → 用户主动点'AI 拆解' → 步骤生成"。也可以是"填完自动触发拆解"。
2. **默认排序方向**:用户只说"按创建时间",未说倒序或正序。推断为新任务在前(倒序),符合常见做法。
3. **任务的'草稿'状态**:推断为"用户刚输入但还没确认拆解"作为初始态,拆解后进入"进行中"。也可以省略草稿态,创建即进行中。
4. **归档区是否需要专门界面**:推断为"主看板隐藏 + 单独的归档区入口可查看",但作者可以选择"删了就消失,无归档区"。
